# `@hackkit/next`

Next.js integration for HackKit Web Apps. Better Auth's HackKit plugin is the runtime composition root; this package wraps that installed runtime with page guards, Core mutations, and HackKit UI provider actions.

Canonical walkthrough: [`docs/guides/next-integration.md`](../../docs/guides/next-integration.md). Reference app: [`apps/web`](../../apps/web).

## Integration path

Wire a HackKit Web App in four steps. Do not rebuild guards or action maps in the app.

### 1. Create and register the runtime

```ts
// lib/runtime.ts
import "server-only";
import { createHackkitRuntime, setHackkitRuntime } from "@hackkit/next";
import { auth } from "./auth";

const runtimePromise = createHackkitRuntime({
	auth,
	afterCurrentUser: async (user, hackkit) => {
		// optional app-specific work (e.g. owner allowlist)
	},
});

setHackkitRuntime(runtimePromise);

export async function getRuntime() {
	return runtimePromise;
}

export async function getPageGuards() {
	return (await getRuntime()).pageGuards;
}
```

The server auth config loads `hackkit(appConfig)` in Better Auth's `plugins` array. `appConfig.database` remains the explicit `DatabaseAdapterFactory`; the plugin does not assume or wrap a database dialect.

`createHackkitRuntime` consumes `auth.$context.hackkit` and owns:

-   `mutations` via `createHackKitMutations`
-   `pageGuards` via `createPageGuards` (with runtime `getCurrentUser` / settings cache)
-   Auth helpers (`getAuthId`, `getCurrentUser`, `getSettingValue`)

### 2. Pass `hackKitUIActions` to HackKit UI

```tsx
// app/providers.tsx
import { hackKitUIActions } from "@hackkit/next";
import { HackKitUIProvider } from "@hackkit/ui";

export function Providers({ children }: { children: React.ReactNode }) {
	return (
		<HackKitUIProvider actions={hackKitUIActions}>
			{children}
		</HackKitUIProvider>
	);
}
```

Do not hand-maintain a local Core action map. Named server actions live inside `@hackkit/next` and delegate to `runtime.mutations`.

Do not pass route maps that contain builder functions from a Server Component — they are not serializable. Omit `routes` to use client-side defaults, pass only string overrides, or supply a client `navigation` adapter for custom admin builders. Server-only helpers (for example onboarding step links) may still import `DEFAULT_HACKKIT_UI_ROUTES` / an app route map.

### 3. Protect routes with runtime-owned page guards

```tsx
// app/onboarding/layout.tsx
import { getPageGuards } from "@/lib/runtime";

export default async function OnboardingLayout({ children }) {
	const guards = await getPageGuards();
	await guards.requireOnboardingAccess();
	return children;
}
```

Common guards: `requireOnboardingAccess`, `requireParticipantAccess`, `requireApprovalPendingAccess`, `requirePermission`, `requireNotBanned`, `requireHackerRegistrationOpenForNewHacker`.

Do not call `createPageGuards` in the app — use `runtime.pageGuards` / `getPageGuards()`.

### 4. Sync plugin actions separately

Plugin server actions stay generated by `hackkit plugin sync` (for example `app/hackkit-plugin-actions.ts`). They use the same registered runtime via `getHackkitRuntime()` / `getRuntime()`.

## Public API

| Export                                    | Role                                                  |
| ----------------------------------------- | ----------------------------------------------------- |
| `createHackkitRuntime`                    | Next adapter around the Better Auth plugin runtime    |
| `setHackkitRuntime` / `getHackkitRuntime` | Module singleton for server actions                   |
| `hackKitUIActions`                        | Provider action map (`satisfies HackKitUIActions`)    |
| `createHackKitMutations`                  | Core → UI mutation bridge (used by the runtime)       |
| `createPageGuards`                        | Low-level guard factory (prefer runtime-owned guards) |
| `actionSuccess` / `actionFailure`         | Shared action result helpers                          |

## Adding a Core mutation

1. Add the method to `HackKitUIActions` in `@hackkit/ui`.
2. Implement it in `createHackKitMutations` (`src/mutations.ts`).
3. Add a thin `"use server"` wrapper in `src/actions.ts`.
4. Include it in `hackKitUIActions` (`src/action-map.ts`).

App-owned bridge files should not need changes. Package tests assert key parity across the UI contract, mutations, and provider map.
